## Backup and recovery

The application uses the named `aeris_feedback` volume, `/state/ledger.sqlite3`. Normal restarts preserve it. Never use `docker compose down -v` to stop this project.

```powershell
$backupName = 'ledger-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.sqlite3'
docker compose exec -T app python scripts/backup_ledger.py --destination "/state/backups/$backupName"
```

This takes an online consistent snapshot, checks SQLite integrity and foreign keys, restores into an independent temporary database, and compares row counts and content hashes. It preserves the live ledger and refuses to overwrite an existing backup. The release verification executed this rehearsal successfully. Backups in the same volume are not protection against disk loss: an operational deployment still needs controlled off-host retention and tested recovery objectives.

For a real recovery, stop writes, preserve the current database and WAL files, restore a verified snapshot into a separate path/volume, point `AERIS_DB` at it, and verify summaries and IDs before returning to service. Do not overwrite a live SQLite database.
